# I04-P01 contract decisions

These decisions record the implementation contract for the current public catalog slice and the LEAD review corrections.

| Decision | Basis | Consequence |
| --- | --- | --- |
| `Template.category` uses the dedicated `TemplateCategory` enum: `GENERAL`, `BIRTHDAY`, `ANNIVERSARY`, `HOLIDAY`. It is distinct from `MediaCategory`, which remains for media assets. | LEAD review correction. | One required topic category per Template; the optional public filter accepts only these values. No tags or dynamic taxonomy. |
| Public responses project only the active current published revision, bilingual copy, identity/version, category, curated layout/presets, and USD price. | BR-TPL-001/002, BR-PRICE-001, API Contract DTO and no-Prisma-serialization rules. | Inactive, missing, or incomplete current revisions are absent from list and return 404 on detail. Project/order writes remain out of this slice. |
| Layout is a versioned contract: v1 supports `PHOTO_FOCUS` and `COLLAGE`, each with 12 months and a maximum of four images per month. Style presets remain a separate field with IDs `classic`, `minimal`, and `vibrant`, each carrying VI/EN display labels. | LEAD review correction; existing product limits and approved preset set. | Projection validates the exact v1 layout shape and supported type; it rejects unsupported versions/types and invalid image/month limits. Preset validation rejects unknown/duplicate IDs and blank labels. No layout editor or rendering UI is included. |
| Search is trimmed, case-insensitive substring matching over VI/EN names and descriptions; it is accent-sensitive under current PostgreSQL collation. SQL wildcards are escaped. | API Contract allowlisted query filter; PostgreSQL has no configured `unaccent` extension. | No extension/locale behavior is introduced. |
| Catalog order is `nameVi ASC, Template UUID ASC`; the opaque base64url cursor carries both. Empty/null names are incomplete. | Task-level contract requirement and stable keyset pagination. | No arbitrary sort input; cursor shape and UUID are validated. |
| Price must be USD, positive, and at most `Number.MAX_SAFE_INTEGER` minor units. | BR-PRICE-001 and safe JSON integer contract. | BigInt is converted only after range validation; Prisma/internal fields do not enter DTOs. |

Migration strategy: because I04-P01 is not deployed, its two migrations directly create/use the dedicated `TemplateCategory` enum. The first adds a nullable category column; the second consumes an explicitly reviewed mapping table, enforces `NOT NULL`, and creates the category/availability index. For a database with existing Templates, prepare `lumical.template_category_backfill` using `backend/scripts/prepare-template-category-backfill.sql`, insert one explicit topic category for every Template, and run `db:migrate`. The migration wrapper refuses to start if mappings are missing, incomplete, invalid, or stale. Never infer the topic from `IMAGE`/`VIDEO`/`AUDIO` or assign a default. Empty databases need no mapping table; synthetic seed runs after migration.

Pagination correctness: SQL applies availability, category/query filters, and the same completeness conditions before ordering and `LIMIT`. The application continues scanning keyset batches if domain projection rejects any returned row, so invalid rows cannot shrink a page, falsify `hasMore`, or skip later valid Templates.

HTTP validation errors raised as `BadRequestException` are mapped to 422 by the global `ApiErrors` filter. OpenAPI documents 422, and Supertest covers invalid category/query/cursor/limit and UUID cases.
